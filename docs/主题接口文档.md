# 素构 Plainstruct 主题接口文档 · 内置标准主题（浅色 / 暗色）

> 面向 **集成方**（把素构构建出的站点嵌进自己的工作流）与 **二次开发者**（改主题、做主题包、程序化调配置）。
>
> 本文覆盖素构内置的两款**标准主题**：
>
> | 主题 ID         | 名称      | 站点类型        | 说明                  |
> | ------------- | ------- | ----------- | ------------------- |
> | `plain-light` | 素构 · 浅色 | `docs`（文档站） | 默认主题：灰白纸感、墨色强调、系统字体 |
> | `plain-dark`  | 素构 · 暗色 | `docs`（文档站） | 暖黑纸感、浅墨强调、系统字体      |
>
> 两款主题的**模板与配置契约完全一致**，差异只在调色板（见 [第 8 节](#8-浅色与深色模式的差异与作用范围)）。
>
> 文档中「内置标准主题」= 以上两款；其余 8 款内置主题（墨阅 / 终端 / 画廊 / 素记 / 专栏 / 日志 / 留白）遵循同一套接口，接口方式通用。

## 1. 先厘清三个「主题」

初上手最容易混淆的三件事，先说清楚：

| 名称                    | 是什么                | 作用对象                       | 在哪配置                               | 本文范围                                                                          |
| --------------------- | ------------------ | -------------------------- | ---------------------------------- | ----------------------------------------------------------------------------- |
| **站点主题**（site theme）  | 决定**构建出的静态站点**长什么样 | 网站产物（`build/` 里的 HTML/CSS） | 站点「主题」页 / `.plainstruct/site.json` | ✅ 本文主题                                                                        |
| **应用界面配色**（app theme） | 决定**素构软件自身界面**的颜色  | 软件窗口 UI                    | 设置 → 个性化                           | ❌ 另一套体系（`src/lib/app-themes.ts`，取值 `light/dark/sepia/mint/ocean/plum/system`） |
| **主题包**（theme bundle） | 一个可分发、可导入导出的 ZIP   | 主题本身                       | `.plainstruct/themes/`             | ✅ 见第 2 节                                                                      |

关键结论：

- 站点主题与应用界面配色**互不影响**。把软件切成「深海」配色，站点产物还是浅色的，反之亦然。
- 标准主题 `plain-light` / `plain-dark` 属于**站点主题**，且只服务**文档站点**（`type: "docs"`）。站点切到博客类型时，主题列表会自动过滤掉它们（见第 10 节）。
- 浅色与深色是**两个独立的主题 id**，不是同一个主题的两种模式。切换 = 换整套主题资源，**不联动、不跟随系统**（见第 8 节）。

## 2. 主题包结构与文件契约

一个主题（含内置标准主题）就是一个固定结构的资源包：

```
主题包/
├── theme.json              # 【必填】元数据 + 配置面板 Schema
├── templates/
│   ├── layout.hbs          # 【必填】整页布局（<html> … </html>）
│   └── page.hbs            # 【可选】正文区模板，缺省直接输出 {{{page.content}}}
├── partials/               # 【可选】Handlebars 局部模板，按文件名注册
│   └── nav.hbs             #   → 模板内用 {{> nav}} 调用，支持递归
└── assets/
    └── style.css           # 【可选】样式，模板内用 {{asset "assets/style.css"}} 引用
```

内置标准主题在仓库里的位置（同一结构，仅打包方式不同）：

```
src/themes/plain-light/
├── theme.json
├── templates/{layout.hbs, page.hbs}
├── partials/nav.hbs
└── assets/style.css
```

> 内置主题通过 `src/themes/manifest.ts` 以 Vite `?raw` 方式在编译期把各文件读成字符串，组装成与「自定义主题（ZIP）」**完全相同的 `ThemeBundle` 结构**。所以内置主题与自定义主题走的是同一条渲染管线，接口完全等价。

**校验规则**（`validateTheme`，导入／启用时执行）：

- 必须存在 `templates/layout.hbs`，否则报 `missing layout`；
- 必须存在 `meta.id`，否则报 `missing id`；
- `templates/page.hbs` 缺失时，正文区回退为直接输出 `{{{page.content}}}`。

## 3. 元数据 `theme.json`（ThemeMeta）

`theme.json` 描述主题身份与配置面板。标准主题 `plain-light` 的开头部分：

```json
{
  "id": "plain-light",
  "name": "素构 · 浅色",
  "version": "4.0.0",
  "type": "docs",
  "author": "MogroWang Studio",
  "description": "默认浅色主题：灰白纸面、墨色强调。",
  "config": [ /* 配置项数组，见第 4、5 节 */ ]
}
```

字段说明：

| 字段            | 类型                 | 必填 | 说明                                                                     |
| ------------- | ------------------ | -- | ---------------------------------------------------------------------- |
| `id`          | `string`           | ✅  | 主题唯一标识。站点配置里就是靠它引用主题。内置主题 id 固定为 `plain-light` / `plain-dark`，**请勿改动** |
| `name`        | `string`           | ✅  | 展示名，出现在主题列表与标题处                                                        |
| `version`     | `string`           | ✅  | 主题版本号（标准主题当前 `4.0.0`）。仅作标识，不参与兼容性判断                                    |
| `type`        | `"docs" \| "blog"` | ⭕  | 主题适用的**站点类型**。缺省按 `docs` 处理。标准主题为 `docs`                               |
| `author`      | `string`           | ⭕  | 作者署名                                                                   |
| `description` | `string`           | ⭕  | 主题说明，列表中以副标题呈现                                                         |
| `config`      | `ThemeField[]`     | ✅  | 配置面板 Schema，**接口核心**，见第 4 节                                            |

**注意 `type` 与 `siteType` 的映射**：`theme.json` 里写 `type`，运行时契约字段名是 `siteType`。加载时会自动转换（`manifest.ts` 的 `toMeta`）：

```ts
// theme.json: { "type": "docs" }  →  运行时 meta: { siteType: "docs", source: "builtin" }
meta.siteType = meta.type === "blog" ? "blog" : meta.type === "docs" ? "docs" : undefined;
meta.source   = "builtin"; // 内置主题固定为 builtin；自定义主题为 custom
```

`source`（`"builtin"` / `"custom"`）由运行时注入，**不要写在 `theme.json` 里**。

## 4. 配置项 Schema（ThemeField）

`config` 数组里的每一项就是一个可自定义的**接口参数**。它既驱动生成可视化配置面板，也是模板里 `{{config.xxx}}` 的取值来源。

### 4.1 通用属性

| 属性            | 类型                            | 必填 | 说明                                              |
| ------------- | ----------------------------- | -- | ----------------------------------------------- |
| `key`         | `string`                      | ✅  | 参数名。模板中通过 `{{config.<key>}}` 读取；也是持久化与跨主题携带的匹配键 |
| `label`       | `string`                      | ✅  | 面板中显示的中文标签                                      |
| `type`        | `ThemeFieldType`              | ✅  | 控件类型，见 4.2                                      |
| `default`     | `string \| number \| boolean` | ⭕  | 默认值。用户未设置时用此值兜底（缺省为空串）                          |
| `min` / `max` | `number`                      | ⭕  | 仅 `number`：取值范围                                 |
| `step`        | `number`                      | ⭕  | 仅 `number`：步进（如 `0.5`、`10`）                     |
| `options`     | `string[]`                    | ⭕  | 仅 `select`：**可选值白名单**。面板渲染为下拉/浮出面板              |
| `tokens`      | `string[]`                    | ⭕  | 仅 `text`：可插入的令牌按钮（如 `{date}`），构建时替换为实际值         |
| `category`    | `string`                      | ⭕  | 面板分组名。缺省时旧式平铺展示                                 |
| `hint`        | `string`                      | ⭕  | 字段下方说明小字，用于交代行为边界                               |
| `hidden`      | `boolean`                     | ⭕  | 为 `true` 时**不在面板渲染**，但配置值仍参与构建与程序化读写            |
| `visibleIf`   | `object`                      | ⭕  | 条件显示，见 4.3                                      |

### 4.2 控件类型 `ThemeFieldType`

| 类型         | 说明     | 面板控件                         | 取值示例                           |
| ---------- | ------ | ---------------------------- | ------------------------------ |
| `color`    | 颜色     | 自绘取色器（触发器 = 色块 + 十六进制值）      | `"#333333"`、`"#e7e5e4"`        |
| `text`     | 单行文本   | 输入框（可带令牌按钮）                  | `"构建于 {date} {time}"`          |
| `textarea` | 多行文本   | 多行输入框                        | `"标签A\|#ff0000\n标签B\|#00ff00"` |
| `number`   | 数值     | 数字输入（支持双击原地输入、偏离默认值一键重置）     | `260`、`15.5`                   |
| `select`   | 枚举     | 浮出选择面板（方向键可选、选中带对勾）          | `"底色"`、`"标题左侧"`                |
| `boolean`  | 开关     | 开关控件                         | `true`、`false`                 |
| `navlist`  | 导航多选列表 | 逐项勾选 + 拖动排序的可视化列表（博客主题顶栏导航用） | —                              |
| `links`    | 链接列表   | 逐条新增「名称 / 链接 / 图标」的可视化编辑器    | `""`（空）                        |

> 标准主题 `plain-light` / `plain-dark` 只用到 `color`、`text`、`number`、`select`、`boolean`、`links` 六种。

### 4.3 条件显示 `visibleIf`

当一个字段只在另一字段取特定值时才需要出现，用 `visibleIf` 声明：

```json
// 自定义字体：仅当正文字体选「custom」时可见
{ "key": "customFont", "visibleIf": { "key": "bodyFont", "equals": "custom" } }

// 构建信息格式：仅当开启「显示构建版本与日期」时可见
{ "key": "footerBuildFormat", "visibleIf": { "key": "footerBuild", "equals": true } }
```

| 子属性      | 说明                                |
| -------- | --------------------------------- |
| `key`    | 依赖的字段名                            |
| `equals` | 依赖字段等于该值时显示                       |
| `oneOf`  | 依赖字段落在该数组之内时显示（与 `equals` 二选一或并存） |

求值时**带默认值兜底**：依赖字段未被用户设置时，用它的 `default` 参与判断。

## 5. 标准主题配置项总表（38 项）

`plain-light` 与 `plain-dark` **各自 38 项，键名、顺序、默认值完全相同**（唯一差异是 `accentColor` 的默认值，见第 8 节）。按面板分组罗列如下。

> 表格中「范围 / 取值」列，方括号内为 `options`（枚举白名单）；`min–max`、`step` 为数值约束。  
> 「作用范围」列注明该项在页面上的生效位置与断点。

### 5.1 站点标识（8 项）

| `key`         | 标签        | 类型        | 默认值      | 范围 / 取值           | 作用范围                   |
| ------------- | --------- | --------- | -------- | ----------------- | ---------------------- |
| `showLogoPc`  | 显示站点 Logo | `boolean` | `true`   | —                 | 桌面端（≥901px）侧栏与顶栏的 Logo |
| `showLogoM`   | 显示站点 Logo | `boolean` | `true`   | —                 | 移动端（≤900px）            |
| `showTitlePc` | 显示站点标题    | `boolean` | `true`   | —                 | 桌面端站点名                 |
| `showTitleM`  | 显示站点标题    | `boolean` | `true`   | —                 | 移动端                    |
| `logoSizePc`  | Logo 大小   | `number`  | `28`     | 16–48，step 1（px）  | 桌面端 Logo 宽高            |
| `logoSizeM`   | Logo 大小   | `number`  | `22`     | 16–40，step 1（px）  | 移动端                    |
| `logoPosPc`   | Logo 位置   | `select`  | `"标题左侧"` | `["标题左侧","标题上方"]` | 桌面端                    |
| `logoPosM`    | Logo 位置   | `select`  | `"标题左侧"` | `["标题左侧","标题上方"]` | 移动端                    |

> 面板标签中带「（移动端 / ≤900px）」含义的项，其 `hint` 均为「窗口宽度 ≤900px 时生效」。

### 5.2 颜色与字体（5 项）

| `key`         | 标签    | 类型       | 默认值（浅 / 暗）            | 范围 / 取值                              | 作用范围                         |
| ------------- | ----- | -------- | --------------------- | ------------------------------------ | ---------------------------- |
| `accentColor` | 强调色   | `color`  | `#333333` / `#e7e5e4` | 任意十六进制色                              | 全站强调色：链接、当前项、焦点环、加载动画、悬停强调等  |
| `bodyFont`    | 正文字体  | `select` | `"system"`            | `["system","serif","mono","custom"]` | `<body>` 字体族                 |
| `customFont`  | 自定义字体 | `text`   | `""`                  | 任意 font-family 栈                     | 仅当 `bodyFont = "custom"` 时生效 |
| `fontSizePc`  | 正文字号  | `number` | `15.5`                | 12–22，step 0.5（px）                   | 桌面端正文字号                      |
| `fontSizeM`   | 正文字号  | `number` | `15.5`                | 12–20，step 0.5（px）                   | 移动端（≤900px）正文字号              |

> `bodyFont` 的四个值分别对应：`system` 系统字体栈、`serif` 衬线（Georgia / Songti SC）、`mono` 等宽、`custom` 用户自填。

| 令牌          | 含义        | 示例产出         |
| ----------- | --------- | ------------ |
| `{version}` | 应用版本号     | `4.1.0`      |
| `{date}`    | 构建日期      | `2026-10-14` |
| `{time}`    | 构建时间（时:分） | `22:35`      |

未识别的令牌**原样保留**。例：`"v{version} · 构建于 {date} {time}"` → `"v4.1.0 · 构建于 2026-10-14 22:35"`。


**友情链接的存储与解析**：每行一条，格式为 `名称|链接|图标`（图标可省略，名称可留空 —— 有图标时渲染为纯图标链接）：

```
项目主页|https://github.com/MogroWang/Plainstruct|asset/logo.svg
GitHub|https://github.com/MogroWang
```

链接需以 `http:` / `https:` / `/` / `./` / `../` / `#` / `mailto:` 开头，否则该条被忽略。

## 6. 配置值 → 渲染产物：注入映射表

标准主题的 `layout.hbs` 把配置值以**三种形式**注入 HTML，再由 `style.css` 消费。理解这张表，就理解了「配置项到底改了什么」。

### 6.1 注入为 CSS 自定义属性（`:root`）

```html
<style>
  :root {
    --ps-accent: {{config.accentColor}};      /* 强调色 */
    --ps-sidebar-w: {{config.sidebarWidth}}px; /* 侧栏宽度 */
    --ps-doc-w: {{config.contentWidth}}px;     /* 正文宽度 */
    --ps-drawer-w: {{config.sidebarWidthM}}vw; /* 移动端抽屉宽度 */
    --ps-logo-w: {{config.logoSizePc}}px;      /* Logo 大小（桌面端） */
  }
</style>
```

紧随主题样式之后还有一段样式，负责**双端（桌面 / ≤900px）独立生效**：

```html
<style>
  body { font-size: {{config.fontSizePc}}px; }
  @media (max-width: 900px) {
    :root { --ps-logo-w: {{config.logoSizeM}}px; }
    body  { font-size: {{config.fontSizeM}}px; }
  }
</style>
```

### 6.2 注入为 `<body>` 的 class 与内联样式

```html
<body class="font-{{config.bodyFont}}{{#if (eq config.pageTransition "淡入")}} ps-anim-fade{{/if}}…"
      {{#if (eq config.bodyFont "custom")}}style="--ps-font-body: {{config.customFont}}"{{/if}} …>
```

| `pageTransition` 取值 | 注入的 class        |
| ------------------- | ---------------- |
| 关闭                  | （无）              |
| 淡入                  | `ps-anim-fade`   |
| 淡入上浮（默认）            | `ps-anim-rise`   |
| 缩放浮现                | `ps-anim-zoom`   |
| 滑入                  | `ps-anim-slide`  |
| 弹性浮现                | `ps-anim-spring` |
| 模糊聚焦                | `ps-anim-blur`   |
| 翻页                  | `ps-anim-flip`   |
| 揭开                  | `ps-anim-wipe`   |

### 6.3 注入为 `<body>` 的 `data-*` 属性

| `data-*` 属性                 | 对应配置项                        | 影响        |

## 8. 浅色与深色模式的差异与作用范围

这是本文最需要说清的一点：**标准主题的「浅色 / 深色」是两套独立资源，而不是同一主题的模式开关。**

### 8.1 二者到底差什么

对 `plain-light` 与 `plain-dark` 做逐文件比对，结论如下：

| 文件                     | 差异                                                                                                                                                  |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `theme.json`           | **仅 `accentColor` 的 `default` 不同**（`#333333` ↔ `#e7e5e4`）；其余 37 项的键、类型、默认值、`options`、`hint` 完全一致；`id` / `name` / `description` 不同，`type` 同为 `docs`  |
| `templates/layout.hbs` | **完全一致**（逐字节相同）                                                                                                                                     |
| `templates/page.hbs`   | **完全一致**                                                                                                                                            |
| `partials/nav.hbs`     | **完全一致**                                                                                                                                            |
| `assets/style.css`     | **仅 `:root` 中 8 个调色板变量不同**（见 7.1）；另有一处极小的实现差异 —— 浅色版末尾多了一段针对侧栏过渡的 `@media (prefers-reduced-motion: reduce)` 块，暗色版没有，仅影响「系统减弱动态效果」下侧栏过渡是否被禁用，与视觉配色无关 |

也就是说：**结构、布局、动效、悬停、内容显示、页脚 全部同源**，唯一的「深浅」体现在 8 个颜色变量 + 1 个强调色默认值上。

### 8.2 各自的作用范围

| 维度           | 浅色 `plain-light` | 深色 `plain-dark`          |
| ------------ | ---------------- | ------------------------ |
| 适用站点类型       | 文档站（`docs`）      | 文档站（`docs`）              |
| 布局 / 组件 / 断点 | 与深色相同            | 与浅色相同                    |
| 可配项（38 项）    | 完全相同             | 完全相同                     |
| 页面背景         | 灰白 `#fafaf9`     | 暖黑 `#141312`             |
| 正文墨色         | 深墨 `#1c1917`     | 浅墨 `#e7e5e4`             |
| 默认强调色        | 浓墨 `#333333`     | 浅墨 `#e7e5e4`（深色底上需亮色才可见） |
| 输出产物         | 完整静态站点，无运行时切换    | 同左                       |

### 8.3 重要行为边界

- **不自动跟随系统深浅**。站点产物中没有 `prefers-color-scheme` 驱动的配色切换（预览里同理）。「跟随系统」只存在于**应用界面配色**，与站点主题无关。
- **切换即换包**。浅 → 深 = 切换主题 id `plain-light` → `plain-dark`，整套资源重新编译渲染，不存在「切换模式只改几个变量」的轻量路径。
  > 二次开发若确实需要「同主题内深浅自适应」，只能在自定义主题里自行加 `@media (prefers-color-scheme: dark)` 覆盖 `:root` 变量。
- **配置不自动迁移到另一款**。但切换时会把**同 key 且类型匹配**的配置值带过去（见 10.3），所以诸如侧栏宽度、字号、动效等设置会在深浅之间保留。

## 9. 模板上下文接口（PageContext）

若你要改主题模板（`layout.hbs` / `page.hbs` / `partials/*.hbs`），可用的数据契约如下（构建与预览共用同一份）。

### 9.1 站点与页面

```handlebars
{{site.name}} {{site.description}} {{site.logo}} {{site.favicon}} {{site.locale}}

{{page.title}} {{page.description}} {{page.date}} {{page.author}} {{page.aigc}}
{{{page.content}}}                    {{!-- 三花括号：已渲染的 HTML，勿转义 --}}
{{page.url}} {{page.relPrefix}} {{page.path}} {{page.fullTitle}} {{page.isHome}}
{{#each page.crumbs}} … {{/each}}     {{!-- 面包屑（移动端顶栏） --}}
```

### 9.2 导航与前后页

```handlebars
{{#each nav}}
  {{this.title}} {{this.url}} {{this.current}} {{this.children}}
{{/each}}
{{prev.title}} {{prev.url}}   {{next.title}} {{next.url}}
```

### 9.3 配置值与资源

```handlebars
{{config.accentColor}}     {{!-- 任意配置项的当前值；缺省时已由 mergeConfigDefaults 用 default 兜底 --}}
{{asset "assets/style.css"}}  {{!-- 资源地址，自动按页面深度换算相对路径 --}}
```

### 9.4 内置 Helper

| Helper               | 说明                                       |
| -------------------- | ---------------------------------------- |
| `{{asset "路径"}}`     | 输出相对当前页的资源地址（自动加 `page.relPrefix` 前缀并编码） |
| `{{#if (eq a b)}}`   | 严格相等比较                                   |
| `{{#if (or a b …)}}` | 任一为真                                     |

`partials/` 下的 `.hbs` 按**文件名**注册为局部模板（`partials/nav.hbs` → `{{> nav}}`），支持递归调用（导航树即靠递归 `nav` 实现）。`templates/page.hbs` 被注册为 `page` 局部模板，`layout.hbs` 里用 `{{> page}}` 引入正文区。

### 9.5 文档正文区（`page.hbs`）产出结构

标准主题的 `page.hbs` 输出固定的骨架，自定义主题若想兼容现状样式，建议保留 class：

```html
<article class="ps-doc">
  <h1 class="ps-doc-title">…</h1>
  <div class="ps-doc-meta">   
  <p class="ps-doc-desc">…</p>
  <div class="ps-doc-body">{{{page.content}}}</div>
  <nav class="ps-pager">…</nav>
</article>
```

## 10. 主题的调用与切换方式

### 10.1 数据模型：站点配置里的主题引用

主题选择持久化在站点文件夹的 `.plainstruct/site.json` 中：

```jsonc
{
  "name": "我的文档站",
  "siteType": "docs",
  "theme": {
    "id": "plain-dark",     // 主题 id
    "source": "builtin",    // builtin（内置）| custom（自定义）
    "config": {             // 仅存「偏离默认值」的键；未列出的键用主题 default
      "contentWidth": 820,
      "accentColor": "#0f766e",
      "bodyFont": "serif"
    }
  }
}
```

对应类型定义：

```ts
interface SiteThemeRef {
  id: string;
  source: "builtin" | "custom";
  config: Record<string, string | number | boolean>;
}
```

**合并规则**：渲染前调用 `mergeConfigDefaults(meta, values)`，按主题 `config` schema 逐项兜底 —— 用户值优先，缺省则取 `default`，再缺省为空串。所以模板里 `{{config.xxx}}` **永远有值**，可放心直接用。

### 10.2 五种调用方式

| 方式         | 入口                                           | 说明                                           |
| ---------- | -------------------------------------------- | -------------------------------------------- |
| **界面操作**   | 站点「主题」页                                      | 挑选主题、调配置面板，即改即生效并自动防抖重建                      |
| **切换主题**   | `useThemeStore().selectTheme(id, source)`    | 写回 `site.json` 的 `theme`，携带兼容配置（见 10.3），随后重建 |
| **改单项配置**  | `useThemeStore().setConfigValue(key, value)` | 即时写入 `theme.config` 并持久化；内置主题被改动时会提示「复制为新主题」 |
| **恢复默认**   | `useThemeStore().resetConfigValues()`        | 清空 `theme.config`，回到该主题的全部默认值                |
| **切换站点类型** | `useThemeStore().applySiteType(type)`        | 站点类型变了，主题自动落到该类型**首个内置主题**，配置重置为空            |

### 10.3 切换时配置如何携带（`carriedConfig`）

从主题 A 切到主题 B 时，**不会**把 A 的配置整体搬给 B，而是按 B 的 schema 逐项筛选：

```ts
// 仅当「键名存在」且「类型吻合」才携带过去，其余回落 B 的默认值
if (f.type === "number"  && typeof v === "number")  carried[f.key] = v;
else if (f.type === "boolean" && typeof v === "boolean") carried[f.key] = v;
else if (f.type === "select") { if (f.options?.includes(String(v))) carried[f.key] = String(v); }
else if (typeof v === "string") carried[f.key] = v;
```

实践含义：

- 加深/浅两个标准主题之间切换（schema 全同），**38 项配置会整体保留**，只有强调色的默认值按新主题算（除非你自己改过 `accentColor`）。
- 切到其它内置主题，只有该主题也声明的同名同类型键会保留，其余回默认。
- 枚举值必须落在**新主题的 `options` 白名单**内才会携带（例如某主题没有「揭页」这个过渡动画，你就带不过去）。

### 10.4 构建 / 预览管线中的位置

```
site.json(theme)
   │
   ├─ ensureActiveBundle()        // 按 id + source 解析出 ThemeBundle
   │     · source=builtin → 从内置清单取
   │     · source=custom  → 读 .plainstruct/themes/<id>/ 文件
   │     · 找不到 → 回退 builtinThemes[0]（plain-light）
   │
   ├─ mergeConfigDefaults(meta, site.theme.config)   // 配置兜底
   │
   ├─ compileTheme(bundle) → render(ctx)             // Handlebars 编译一次，渲染多页
   │     · 注册全部 partials/
   │     · 注册 page 局部模板（缺省 {{{page.content}}}）
   │     · 注册 helper：asset / eq / or
   │
   └─ renderPage() → HTML 字符串 → 写入 build/
```

模板变更、配置变更、站点保存后都会触发**防抖重建**，保证「预览即产出」。

### 10.5 复用与二次开发路径

| 目标             | 做法                                                                           |
| -------------- | ---------------------------------------------------------------------------- |
| 只调整配置          | 直接在主题页改，保存在站点 `theme.config` 中（**不改主题文件**）                                   |
| 改样式 / 模板，且希望固化 | 主题页「复制内置主题为新主题」→ 在主题制作器里编辑模板与样式（含实时预览）                                       |
| 分发给他人          | 主题页「导出 ZIP」；对方「导入 ZIP」即可使用                                                   |
| 手动放置           | 解压到站点的 `.plainstruct/themes/<id>/`（需含 `theme.json` 与 `templates/layout.hbs`） |

> 内置主题（含 `plain-light` / `plain-dark`）**不可删除、不可原地修改**；任何改动都体现为站点级的配置覆盖。想让改动成为主题的一部分，必须复制为自定义主题。

## 11. 使用说明与注意事项

1. **站点主题 ≠ 应用配色。** 用户在设置里换的「浅色/深海/紫檀」只影响软件界面，不影响构建产物；站点深浅只由站点主题决定。
2. **两款标准主题只服务文档站。** 它们 `type: "docs"`，切到博客站点时不会出现在主题列表中（系统会自动改用该类型下的首个内置主题）。想让站点外观独立于站点类型，请复制为自定义主题并改 `type`。
3. **断点是 900px。** 所有带 `M` 后缀或标注「移动端」的配置项，都在 `@media (max-width: 900px)` 内生效；字号、Logo 大小等「双端独立」项在桌面与移动分别取值，一处修改不会影响另一端。
4. **内置主题的配置改动不会写回主题文件。** 它只保存在该站点的 `.plainstruct/site.json` 中，换站点即失效。需要固化请「复制为新主题」。
5. **切换主题只携带兼容配置。** 同名同类型（枚举还需在白名单内）的键才会保留，其余回默认 —— 切换后请回看面板，确认关键项符合预期。
6. **`accentColor` 是标准主题唯一的颜色旋钮。** 想要更深度的配色定制（背景、墨色、分隔线等），需复制主题后改 `assets/style.css` 的 `:root` 变量（见第 7 节）。
7. **`bodyFont = "custom"` 必须同时填写 `customFont`**，否则回退为 `system-ui, sans-serif`。
8. **数值项请遵循 `min` / `max` / `step`。** 面板会按范围夹取；程序化写入虽可越界，但会导致面板显示与产物不一致。标准主题的取值范围见第 5 节。
9. **文本类配置会被注入 HTML 与 `<style>`，请注意转义安全。** `customFont`、`footerNote`、`footerBuildFormat` 等会写入页面；颜色、数值、枚举类请保持在白名单/合法格式内，避免填入能破坏 HTML/CSS 的字符（如 `</style>`、未配对引号）。
10. **`footerLinks` 有格式约定。** 每行 `名称|链接|图标`，链接必须带协议或相对前缀（`http(s):` / `/` / `./` / `../` / `#` / `mailto:`），否则该行被忽略；名称留空且有图标时渲染为纯图标链接。
11. **`footerBuildFormat` 的令牌**只有 `{version}` / `{date}` / `{time}` 会被替换，其余原样输出；格式留空时回退为 `"构建于 {date} {time}"`。
12. **加载动画依赖 JS。** `loadingAnim` 的入口与显示由页面引导脚本（`html.ps-js`）控制，脚本被禁用时不呈现，属预期行为。
13. **动效尊重系统「减弱动态效果」。** `pageTransition` 与 `loadingAnim` 在 `prefers-reduced-motion: reduce` 下自动退化。
14. **兼容性兜底。** `navCurrent` 的历史值「左侧标记」按「下划线」处理；`sidebarTogglePc` 的旧取值（边缘/顶部/底部）统一按「右下角」处理。
15. **校验与回退。** 主题缺少 `templates/layout.hbs` 或 `meta.id` 会被拒绝启用；配置中引用的主题 id 不存在时，回退到内置第一个主题（`plain-light`）。
16. **`config` 与 `site` 数据同源。** 预览与构建走同一条渲染管线，面板里所见即产物中所见，无需担心「预览对、构建不对」。
